# Data dictionary

> Generated by `server/scripts/dictionary.ts` from the code. Don't edit by hand: change the code, then run `npm run dictionary -w server`.

27 built-in categories, 187 fields, 11 profile lines, 25 stored collections.

Every record also carries: `validFrom` and `validTo` (dated categories), `sensitivity` (the owner’s choice for that entry; unset means the default), `notes`, `source` (who created it), `updatedBy` (who last changed it), and timestamps.

## Owner profile (computed)

Nothing is stored on the profile: each line is worked out from the categories every time (profile.ts), and is as sensitive as the parts it shows. The basic profile is every standard line; secret lines never leave.

## Stored collections

Everything a node stores, one SQLite table each.

### Account

| Collection | Holds |
|---|---|
| `owners` | How the owner signs in: passkeys, password hash, authenticator secret, recovery code hashes, display preferences. Their name and email live in Names and Contact methods. |
| `nodes` | This node: its Node ID, signing key reference, key history, addresses and address history, claim state, hosting. |

### Records

| Collection | Holds |
|---|---|
| `domainDefs` | Custom categories the owner creates (ids start x_). Built-in categories live in code, not here. |
| `records` | Every entry in every category: its data, validFrom/validTo, notes, who created it (source) and last changed it (updatedBy). |
| `recordVersions` | History: a copy of a record after each change (or before a delete), with who made it. Powers undo and restore. |

### Assistants

| Collection | Holds |
|---|---|
| `reviews` | Changes an assistant proposed that wait for the owner (encrypted), and their outcome. |

### Documents

| Collection | Holds |
|---|---|
| `documents` | Documents: title, kind, date, status (inbox/filed), notes, extracted text, links to records, suggestions, pages. |
| `files` | The stored bytes of each page or file (encrypted), with type, size and who added it. |

### Sharing

| Collection | Holds |
|---|---|
| `shares` | Expiring share links for documents. |
| `copies` | Snapshots of entries sent to someone (link, file or email text), encrypted, with views and downloads counted. |
| `publicProfile` | What the owner shows publicly: which Names entry is the public name, chosen profile lines, record sections, photo. |
| `grants` | What the owner lets a contact see: the basic profile, extra profile fields, or whole categories (all or current only). |

### Contacts

| Collection | Holds |
|---|---|
| `parties` | People and organisations in the owner’s life: type, name, contact methods (one shape), notes, affiliations, their node if they run Little Dipper, and what they last shared with the owner. |
| `nodeLinks` | A connection with another Little Dipper: its Node ID and address, status, the tokens each side holds, timeline. |
| `connectionRequests` | Incoming and outgoing requests to connect, with what each side asked for and offered. |
| `invites` | Invite links the owner created to connect with someone. |

### Messages

| Collection | Holds |
|---|---|
| `messages` | Messages to and from connected nodes (encrypted), with delivery status and retries. |

### Assistants & apps

| Collection | Holds |
|---|---|
| `apiKeys` | Every credential: the browser session, app and assistant keys (scopes, mode, secret fields), peer tokens. Only hashes are stored. |
| `oauthClients` | Assistant platforms registered through OAuth (self-reported name, redirect addresses). |
| `oauthCodes` | Short-lived authorization codes during an OAuth connection. |
| `oauthTokens` | Hashes of OAuth access and refresh tokens, each tied to an assistant key. |

### System

| Collection | Holds |
|---|---|
| `audit` | The activity log: who did what, when, in plain words. |
| `notices` | Notifications for the owner (Review waiting, digests, ended connections), and which were dismissed. |
| `backups` | Backups kept on the node itself, and backup settings. |
| `challenges` | One-time sign-in and passkey challenges. |
